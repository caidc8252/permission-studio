# 合同模块关系图设计

## 目标

把“合同模块”页的双栏穿梭框替换成类似脑图的完整关系图，让用户直接看到一个合同与菜单树、组件之间的关系，并在图上完成启用、移除和批量联动。关系图只替换编辑交互，继续使用现有 `PermissionDraft`、变更审查和 PR 提交流程。

## 交互模型

- 左侧保留合同类型选择，`TEST` 仍只读且不出现在可编辑列表中。
- 右侧画布以当前合同为根节点，向右展开“菜单”和“组件”两个分支。
- 菜单节点按照 `parentMenuCode` 组成层级树；组件作为“组件”分支的叶子节点。
- 所有模块都显示在图中。已启用节点使用蓝色强调和实线关系，未启用节点使用灰色弱化和虚线关系，草稿中刚发生变化的节点显示“待新增”或“待移除”标记。
- 每个模块节点有明确的复选控件。点击父菜单会递归启用或移除全部后代；部分后代启用时父节点显示半选；全部后代启用后父节点自动启用。折叠状态不影响递归联动范围。
- 分支节点支持展开和收起。收起只改变画布显示，不修改草稿。
- 搜索按名称或代码匹配，自动展开匹配节点的祖先、突出匹配结果并将第一个结果移动到视口中央；清空搜索恢复用户原有折叠状态。
- 节点可在画布内拖动以临时整理视图；提供缩放、平移、适应画布、小地图和“自动整理”按钮。节点位置不写入权限配置。
- 不允许用户自由创建、重连或删除边。边表达模型中已有的合法层级，权限变更只能通过节点复选控件发生，避免产生无效结构。

## 架构

- 使用 `@xyflow/react@12.11.3` 提供画布、节点拖动、缩放、平移、小地图和可访问的图交互。
- 使用 `@dagrejs/dagre@3.1.1` 根据当前可见树生成从左到右的稳定布局，不自行实现图布局算法。
- 新增纯领域投影模块，把 `PermissionStudioModel + PermissionDraft + contractType + collapsed state` 转换为与 UI 库无关的节点、关系和选择状态；级联选择也放在该模块中，便于独立测试。
- React Flow 适配组件只负责把投影转换成 React Flow 的 `Node`/`Edge`、处理视口以及将用户操作回传为新的 `PermissionDraft`。
- `ContractModuleEditor` 继续负责合同切换和 `onDraftChange`，不改变 `StudioShell` 的持久化、锁定、刷新、审查或 PR 行为。

## 组件边界

- `contract-module-graph.ts`：构建树、计算折叠后的可见节点、三态选择、级联后的菜单/组件成员集合、搜索匹配和稳定布局输入。
- `contract-module-node.tsx`：渲染合同、分组、菜单、组件四类节点；模块节点暴露原生可访问复选语义，父节点支持 `aria-checked="mixed"`。
- `contract-module-graph.tsx`：封装 React Flow、Dagre 布局、搜索定位、工具栏、图例和节点事件。
- `contract-module-editor.tsx`：保留合同列表，使用关系图替代 `DualListEditor`。

## 状态与数据流

1. 当前合同、模型和草稿生成完整关系图投影。
2. 用户切换节点后，纯领域函数计算规范化成员集合。
3. 编辑器分别调用现有 `setContractOwnerMembership` 更新菜单或组件覆盖值。
4. 新草稿通过 `onDraftChange` 回到 `StudioShell`，继续触发本地持久化、变更托盘、审查和 PR 流程。
5. 切换合同或刷新模型时重新投影；本地节点位置与折叠状态按合同隔离，不进入权限草稿。

## 边界情况

- 空合同仍显示根节点与两个分支，所有模块为未启用状态。
- 没有菜单或组件时，对应分支显示空状态节点。
- 菜单树循环和缺失父节点由现有模型校验拦截；投影层仍使用访问集合防止异常数据导致死循环。
- 编辑器被 `fieldset disabled` 锁定时，关系图中的权限控件和工具栏编辑操作均不可用，但允许查看、缩放和平移。
- 大图仅渲染当前展开的节点；React Flow 使用 `onlyRenderVisibleElements`，搜索和适应画布不改变权限数据。
- 窄屏下合同列表位于画布上方，画布保持固定最小高度，避免重新出现需要滚动很久才能操作的问题。

## 验收标准

- 进入合同模块页即可看到当前合同的根节点、菜单树和组件分支，不再出现双栏穿梭框。
- 可以缩放、平移、拖动节点、自动整理、适应画布和使用小地图。
- 点击父菜单递归联动所有后代；子节点部分选中显示父节点半选；全部选中自动选中父节点。
- 折叠分支后执行父节点联动仍覆盖隐藏后代。
- 搜索名称或代码能突出并定位匹配节点。
- 节点变更准确写入现有草稿，变更托盘、审查与 PR 流程继续显示相同的菜单/组件差异。
- 键盘用户可以聚焦节点复选控件、切换状态和使用图工具栏；状态不只通过颜色表达。
- 关系图领域测试、组件交互测试、现有全量测试、类型检查、Lint 和生产构建全部通过。

## 非目标

- 不修改 pep-webapp 的权限模型格式。
- 不把节点坐标提交到 pep-webapp。
- 不允许编辑菜单父子结构，也不允许任意连线。
- 本轮不把角色权限页改成关系图。
